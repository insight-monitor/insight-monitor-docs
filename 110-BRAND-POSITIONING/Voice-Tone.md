# Voice and Tone

## Core principle
All Insight Monitor communication must reflect what the system actually does: probabilistic estimation from observable signals. Claims must be traceable to specific signals, inferences, or documented limitations.

## Allowed language

| Use | Instead of |
|-----|------------|
| estimates, infers, classifies | understands, knows, sees |
| probable intent, task hypothesis | actual intent, real purpose |
| with N% confidence | with certainty |
| evidence suggests | the system determined |
| limited to monitored-device signals | full activity visibility |
| behavioral intelligence | mind reading |

## Forbidden language

| Phrase | Why |
|--------|-----|
| "The system knows" | Implies certainty that does not exist |
| "Understands what you are doing" | Anthropomorphic, overclaims capability |
| "Sees everything" | Violates honesty about blindspots |
| "Guarantees accuracy" | No probabilistic system guarantees correctness |
| "Catches all distraction" | False negative rate is never zero |
| "Reads intent" | Intent is estimated, not read |

## Tone guidelines
- **Professional** but not corporate. Avoid jargon where plain language works.
- **Transparent** about limitations. Every strength claim should be balanced by an acknowledged boundary.
- **Evidence-based.** Statements about system behavior must cite the mechanism or inference path.
- **No false binaries.** Nothing is "productive" or "unproductive" in absolute terms — always contextual.
